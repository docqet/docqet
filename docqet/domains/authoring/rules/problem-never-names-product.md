---
docqet: rule
id: problem-never-names-product
domain: authoring
name: A problem never names the software
concepts: [concept:problem]
why: >-
  So a problem stays true whatever solves it, and the solution can change
  without the problem changing.
---

A problem's name, description and cost name no screen, capability, feature or
part of the software. Ask whether it would still be true if the software
didn't exist. Nothing can check this: it holds because people write it so,
and reviewers look for it.
