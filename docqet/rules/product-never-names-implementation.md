---
docqet: rule
id: product-never-names-implementation
name: Product docs never link to technical docs
why: >-
  Product docs say what the software does in the business's words, so they stay
  true however it's built, and stay readable by people who don't read code.
---

Technical docs link to the product, through a component's capabilities, and
never the other way.

The same holds one space up: problem docs never link to the solution, so
links only point toward why. A problem names only the personas who have it.
