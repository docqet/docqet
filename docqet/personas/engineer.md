## Needs

- To know what a capability is meant to do, how stable it is, and the rules it
  follows, before changing its code.
- To find out a doc is wrong, or an annotation names nothing, before a
  reviewer does.
- To keep the docs current without it taking longer than the change itself.

## Knows

The codebase and its conventions, git, and the CI it runs in. Knows the domain
from working in it, not always in the business's own words.

## Context

At a terminal and an editor, often with an agent doing part of the work.
Docqet is one step in a change, so it has to be quick and say plainly what to
fix.

## Cares about

Docs that stay true. They'll stop reading them the first time they describe
code that's long gone.
